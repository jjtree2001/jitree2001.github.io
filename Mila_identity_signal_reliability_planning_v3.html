Using hierarchical variance partitioning to optimise identity-level ratings

A shareable workflow for Mila’s rating data: the goal is to best estimate the stable friendliness 'signal' attributable to each face identity, identify the noise sources, and use those variance components to decide whether future work should add raters or add images per identity. This will also serve to demonstrate the additional utility of LMMs as they naturally partion variance!

1. Data context and objective

Mila’s design has 47 raters, two sessions, 100 face images, and 20 identities with 5 images per identity. Ratings are on a 1–9 ordered scale - relating to how friendly they would rate each image presented. The central objective is to improve the estimate of identity-level friendliness: the stable consensus score for a particular person, abstracting over the particular raters and images sampled which also includes the fact we ran this twice (to look at test-retest reliability which I discuss elsewhere).

Target signal: stable identity-level consensus friendliness (this is essentially an aggregate of the ratings given by participants across the five exemplar images for each of the 20 individuals).
Design levers: number of raters (pariticipant N) and number of images per identity.
Practical question: once we have around 50 raters, is the next reliability gain better achieved by adding more participants or more exemplars of each identity?

2. Stage 5: Bayesian ordinal hierarchical variance decomposition

Earlier analyses (Stages 1-4) showed that aggregated ratings were reliable and stable (using ICC and test-retest reliaability). Stage 5 shifts the question from “is it reliable?” to “why is it reliable?” The hierarchical model partitions raw ratings into a stable identity signal and several sources of noise: participant scale-use, image-specific effects, participant-specific taste, session shifts, and residual response-level variation.

Because the dependent variable is a 1–9 ordered rating, the preferred model is a Bayesian cumulative-logit model rather than a Gaussian model. Variance components are interpreted on the latent response scale. In a cumulative-logit model, the fixed latent residual/logistic variance is π²/3.

Model

fit_ord <- brm(
  Rating_ord ~ Session + Gender +
    (1 | PID) +                # participant scale-use / generosity
    (1 | PID_Session) +        # participant session-specific shifts
    (1 | Identity) +           # stable identity friendliness
    (1 | File) +               # image-specific effects
    (1 | PID_Identity) +       # participant-specific taste
    (1 | Identity_Session),    # identity-specific session instability
  data = dat_ord,
  family = cumulative("logit"),
  prior = c(
    prior(normal(0, 1), class = "b"),
    prior(student_t(3, 0, 1), class = "sd")
  ),
  chains = 4,
  cores = 4,
  iter = 2000,
  backend = "cmdstanr",
  control = list(adapt_delta = 0.95, max_treedepth = 12)
)

The model was computationally healthy: Rhats were close to 1, effective sample sizes were acceptable, there were 0 divergent transitions, and there was no problematic treedepth behaviour.

3. Stage 6: Rouder-inspired reliability planning

The final stage uses the logic of Rouder’s signal-to-noise framework, adapted to the rating paradigm. In Rouder’s cognitive-task examples, increasing trials improves reliability by averaging down trial noise (basically CLT in a trench-coat!). Here, the analogous target is stable identity-level friendliness, and the relevant design levers are number of raters and number of images per identity.

reliability = identity signal / (identity signal + design-adjusted noise)

Identity variance is treated as the stable signal. File/image effects, participant scale-use, participant-by-identity taste, and residual/logistic variance are treated as sources of noise that can be reduced by aggregation.

Absolute reliability

Absolute reliability = Var_Identity / [ Var_Identity + Var_File / n_images + Var_PID / n_raters + Var_PID_Identity / n_raters + Var_Residual / (n_raters × n_images) ]

Consistency reliability

Consistency reliability = Var_Identity / [ Var_Identity + Var_File / n_images + Var_PID_Identity / n_raters + Var_Residual / (n_raters × n_images) ]

The consistency version removes general participant scale-use/generosity (Var_PID), because it focuses more on whether identities are ranked similarly rather than whether raters use exactly the same absolute scale values.

5. Design optimisation: in this case where should reliability gains best come from?

With 5 images fixed, increasing from 47 to 100 raters only raises predicted absolute reliability from approximately .735 to .762. Additional raters continue to average down participant scale-use, idiosyncratic taste, and residual noise, but they do not average down image-specific presentation effects - which is where the bigger design benefit lives.
By contrast, holding sample size near the current level and increasing the number of images has a larger payoff. A design with approximately 50 raters and 10 images is predicted to reach absolute reliability of approximately .820, with consistency reliability around .850. Why? Its all about the denominator baby.

This neatly illustrates that Rouder and Mehrvarz’s proposal can be understood as a signal-to-noise account of reliability that is closely aligned with the logic of the central limit theorem - that is always look at the size of sample you have obtained for the estimates you are after. Their suprisingly simple key point is that reliability is not simply a fixed property of a task; it depends on the size of the target signal estimation recovery, relative to the the amount of noise, with the latter being the obvious design optimisation target. Put simply, this 'noise' or the 'denominator' in all these reliability ratios is attenuated by the sampling design used to average that noise down! Here, although participant variance was large in the raw model, it was already being divided by 47 raters, whereas image-specific variance was divided by only 5 images. Therefore, after aggregation, image-sampling noise remained the larger practical contributor to the denominator of the reliability ratio. In simplest terms, adding +1 to 47 gets you less benefit that adding +1 to 5 (shades of Spearman-Brown prophecy here boys and girls - if this point isn't clear I have added some teaching content at the end)

7. Why this matters for downstream empirical work

Optimising the mean identity-level estimate is important because this estimate often becomes the dependent variable in downstream analyses. The aim is usually not just to know whether raters agree, but to generate a stable distribution of consensus scores across a population of identities, and then ask what predicts variation in that distribution.

For example, once each identity has a reliable friendliness estimate, one can test whether facial symmetry, averageness, sexual dimorphism, skin texture, age cues, personality impressions, or other properties explain why some identities are judged as more friendly than others. If the identity score is estimated from too few images or raters, such covariate analyses risk being dominated by image-specific noise or idiosyncratic rater effects.

Design recommendation: the current design of 47 raters × 5 images is acceptable, but it is not maximised. If future work aims to improve reliability, the more efficient next step is to increase the number of images per identity. A practical target is around 50 raters × 10 images per identity, which the model predicts would move absolute reliability from about .735 to about .820.

8. Full annotated Stage 6 code

# ============================================================
# Stage 6. Rouder-inspired reliability planning
# ============================================================
#
# Aim:
# Use the variance components from the Stage 5 ordinal hierarchical
# model to answer a design question:
#
#   How many raters and how many images per identity are needed to
#   recover a reliable identity-level friendliness estimate?
#
# This is the design analogue of Rouder's trial-planning logic.
# In Rouder-style terms:
#
#   reliability = signal / (signal + noise)
#
# But here the noise is design-adjusted:
# - image-specific noise is reduced by sampling more images
# - rater-related noise is reduced by sampling more raters
# - residual response noise is reduced by the total number of ratings
#
# Target signal:
#   stable identity-level friendliness
#
# Design levers:
#   1. number of raters per identity
#   2. number of images per identity
# ============================================================

var_draws <- draws_full %>%
  transmute(
    draw = row_number(),

    # Participant scale-use / generosity.
    Var_PID = sd_PID__Intercept^2,

    # Target signal: stable identity-level friendliness.
    Var_Identity = sd_Identity__Intercept^2,

    # Image-specific presentation effects.
    Var_File = sd_File__Intercept^2,

    # Participant-specific taste for particular identities.
    Var_PID_Identity = sd_PID_Identity__Intercept^2,

    # Fixed residual variance for the cumulative-logit latent scale.
    Var_Residual = pi^2 / 3
  )

design_grid <- expand_grid(
  n_raters = 1:100,
  n_images = 1:10
)

planning_draws <- design_grid %>%
  crossing(var_draws) %>%
  mutate(
    reliability_absolute =
      Var_Identity /
      (
        Var_Identity +
          Var_File / n_images +
          Var_PID / n_raters +
          Var_PID_Identity / n_raters +
          Var_Residual / (n_raters * n_images)
      ),

    reliability_consistency =
      Var_Identity /
      (
        Var_Identity +
          Var_File / n_images +
          Var_PID_Identity / n_raters +
          Var_Residual / (n_raters * n_images)
      )
  )

planning_summary <- planning_draws %>%
  group_by(n_raters, n_images) %>%
  summarise(
    absolute_mean = mean(reliability_absolute),
    absolute_lower = quantile(reliability_absolute, .025),
    absolute_upper = quantile(reliability_absolute, .975),

    consistency_mean = mean(reliability_consistency),
    consistency_lower = quantile(reliability_consistency, .025),
    consistency_upper = quantile(reliability_consistency, .975),

    .groups = "drop"
  )

planning_summary

key_designs <- planning_summary %>%
  filter(

      (n_raters == 100 & n_images == 5) |
      (n_raters == 50 & n_images == 10)
  ) %>%
  mutate(
    Design = case_when(

9. Teaching primer: why more sampling often means better measurement

A useful way to think about almost any empirical estimate is that it is based on a sample from some distribution, and its precision depends on how much of that distribution has been sampled. This applies whether the estimate is a simple mean, a reliability coefficient, a participant-level task score, a stimulus rating, or a model-derived latent trait estimate.

9.1 Every estimate sits on a sampling distribution

Suppose we want to know someone’s “true” average mood, an identity’s “true” consensus friendliness, or a participant’s “true” Stroop effect. We never observe that value directly. Instead, we observe a limited sample.

observed estimate = target signal + sampling noise

The above is just basically Classical Test Theory's point - Sampling noise comes from whatever observations we happened to collect: people, items, trials, raters, images, days, tasks, or occasions. A single observation is usually noisy. What is actually kinda amazing is the point that Central limit thereom shows that if u want to drive that sampling noise down then a mean over many observations is usually the best way to do it. (Ok for the purests it doesn't have to be a mean, the point is to make sure you are better estimating the variance)

9.2 The core principle is aggregation

Central limit theoreoms point is that if noise is partly idiosyncratic, averaging more observations reduces its influence (the phrase is usually "random errors cancel out"). This is the basic central-limit-theorem intuition: more observations produce less sampling error and therefore a more precise estimate. For a simple mean, this is familiar:

SE(mean) = SD / √N

Importantly, precisely the same logic appears in reliability theory. Reliability improves when the stable signal remains the same but the error term is averaged down - and this is what is being illustated in the worked example above and sits at the heart of Rouder and Mehrvarz’s (2026) proposals. When you stop and thinking about it, this point actually appears literally everywhere in the reliability analytical approaches (examples are below)

9.3 Different reliability frameworks use different sampling units

Framework Sampling unit that improves reliability Interpretation
Cronbach’s alpha / Spearman–Brown Items More items usually produce a more reliable total or mean score because item-specific error averages down.
Rouder-style task reliability Trials More trials produce a more reliable participant-level task effect because trial-level noise averages down.
ICC average-rater logic Raters An average across raters is more reliable than a single rater because individual rater error is averaged down.
Mila’s identity-rating design example above Raters and images More raters reduce observer noise; more images reduce stimulus-sampling noise.

9.4 The biggest raw variance component is not always the best target

A tempting mistake is to look at the raw variance components and assume that the biggest component is the one that should be sampled more. But what matters for design optimisation is the design-adjusted contribution to uncertainty.

In the example from Mila’s study: participant variance was large in the raw model. However, participant-related noise was already divided by about 47 raters. Image-specific noise was smaller in raw terms, but divided by only 5 images. So after aggregation, image-sampling noise remained the more important bottleneck.

Design lesson: do not simply sample more from the largest raw variance component. Sample more from the source that still contributes the most uncertainty after the current design has averaged things down.

9.5 Generalizability Theory makes this logic explicit

Generalizability Theory (Cronbach's approach that everyone ignored after he told people to stop using alpha) - is perhaps the cleanest formal expression of this idea. It asks what the relevant sources of measurement variation are and how many samples are needed from each source. Those sources might be persons, items, raters, occasions, tasks, stimuli, or sessions.

Once those variance components are estimated, we can ask design questions such as whether reliability would improve more by adding items, raters, occasions, or stimuli. This is exactly the logic used here: estimate the variance structure with a hierarchical model, then ask which sampling dimension should be increased to improve the target estimate. The answer is typically pretty simple - if you have a very small initial sample, well make it bigger dummy. (I find this amusing given all the obsession about power analyses)

9.6 General lesson

Reliability is not only a property of a measure. It is a property of a measure under a particular sampling design. The same construct can look unreliable under sparse sampling and highly reliable under richer sampling.

Key question: reliable with how many items, trials, raters, stimuli, or occasions?

When trying to improve an estimate, the best question is:

Which distribution have we sampled least well, relative to how much noise it contributes?

If the problem is item noise, add items. If the problem is trial noise, add trials. If the problem is rater noise, add raters. If the problem is stimulus-sampling noise, add stimuli. If the problem is occasion-level fluctuation, add occasions.

Unifying principle: more sampling improves precision, but only for the source of noise being sampled. The best design improvement is to increase the sampling dimension that still contributes the most uncertainty to the target estimate.
